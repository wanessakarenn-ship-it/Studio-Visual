# Storage v2 — local persistence and recovery
StorageAdapter provides asynchronous load/save; initial localStorage implementation uses one envelope containing current and prior valid revisions, so one setItem replaces the pair. Explicit recovery creates a new document ID and preserves corrupt bytes. Import validates and migrates; legacy storage is read-only. Autosave debounces 800ms, serializes writes and reports success only after persistence. Failed writes retain pending content for retry.
Limitations: localStorage is synchronous and revision checks are not atomic across tabs; concurrent editing is unsupported until IndexedDB transactional storage or a cross-tab lock is implemented. No maximum autosave interval or page-close flush yet; UI must surface pending/error state. Backup JSON excludes local asset bytes; asset storage is pending. This package is not wired to the legacy UI. Immer patches remain pending; no dependency changes.
